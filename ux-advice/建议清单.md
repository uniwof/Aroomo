## 一、界面布局

### L1【P0 缺陷】桌面 1000–1476px 宽时，各页面左侧内容被侧栏盖住
- **现状（实测）**：`page.html` 第 82 行媒体查询给 `main` 设 `margin-left:var(--side)`（288px），但第 96 行 `main{margin:0 auto}` 写在后面，同优先级后者胜出。`measure.py` 实测 `main` 左边缘：1000 宽 = 42px、1100 = 92px、1280 = 182px、1440 = 262px，侧栏右边缘恒为 288px → 1100 宽时被盖约 180px。截图 `light-1440-members.jpg` 里「37 位」只剩「7 位」，`light-1440-room-top.jpg` 里「阵容」缺「阵」；底部输入框偏移是对的，所以还和消息列左右错位。
- **改法**：①侧栏常驻的断点从 1000 提到 1200（288 + 900 内容 ≈ 1188），1000–1199 宽改用抽屉（与手机同逻辑）；②≥1200 时用 `body{display:grid;grid-template-columns:var(--side) 1fr}` 或把偏移写在 `main{margin:0 auto}` 之后：`main{margin-left:calc(var(--side) + max(16px,(100vw - var(--side) - 900px)/2))}`；`.cbox` 用同一中心线；③不要用 `overflow-x:hidden` 掩盖（放大时会把内容藏起来）；④ui_test 加断言：1000/1100/1199/1200/1280/1440 六个宽度下 `h1.left ≥ 侧栏右边 + 16`，且消息列与输入框中心线差 ≤4px。
- **为什么符合宗旨**：低视力用户常靠浏览器放大，1440 屏放大到 125–150% 正好落进 960–1150 的视口区间，左侧字被吃掉等于看不见。
- **借鉴**：CSS 层叠顺序问题，无需外部来源；断点思路采纳 Agnes 评审。**改动量**：小。**风险**：低；ui_test 中依赖 1000px 常驻侧栏的用例要改成 1200。
- **评审**：Groq「改 grid、加 overflow-x:hidden」→ grid 采纳，overflow-x 驳回；Agnes「1280 以下用抽屉」→ 部分采纳（取 1200，再大就浪费 1200–1279 的可用宽度）。

### L2 项目页头首屏太满，手机上用户自己的问题被挤到第二屏
- **现状**：`light-390-room-top.jpg`：标题两行 + 状态下拉 + 模式按钮 + 发起时间 + 「阵容 · 4 位」横滑卡 + 「成员与角色/打分/成员互评」三按钮，约 430px 高，用户的问题从约 470px 才开始。
- **改法**：页头只留：标题（最多两行）+ 一行 19px 文字胶囊「讨论中 · 4 位成员 ›」（现有描边胶囊样式，不加新色；`aria-expanded` 控制展开现在的阵容横滑卡与「成员与角色」）；「打分 / 成员互评」移到结论卡（L3）和「＋」菜单；状态下拉改自动状态（D4）；页头模式按钮去掉（M3）。目标：390 宽、标准字号下页头 ≤200px；不允许用 `max-height + overflow:hidden` 截断（大字号下会切字）。
- **为什么**：少看屏，一屏回答一个问题「我问了什么、讨论到哪了」。
- **借鉴**：Slack / Discord 频道头只放名字 + 成员数，成员列表点开才出现。**改动量**：中。**风险**：ui_test 里页头按钮定位要改。
- **评审**：Agnes「160px 太紧，留 200px」采纳；Groq「胶囊黄色违背 C1、破坏漫画风」驳回（胶囊用现有描边样式，不是黄色）；Groq「max-height 截断」驳回。

### L3 每轮结束给一张「结论卡」，页头钉一行「最新结论」
- **现状**：裁判的裁决与其他成员发言同为一个彩色气泡（`light-1440-room.jpg` 最后的紫色气泡），权重相同；回到项目要滚到底才看到结论。
- **改法**：裁判发言后渲染结论卡（`<section aria-labelledby>` + `<h2>`）：漫画「大格」样式，左上贴纸「裁决」（现有贴纸样式）；首句结论 23px 粗体；「理由」最多 2 行 19px，「仍有分歧」只在确有分歧时出现；底部三个 ≥48px 真按钮「采纳」「打回再议」「打分」，Tab 顺序与视觉顺序一致。页头标题下一行「最新结论：……」，点它跳到卡片；卡上一个「听结论」（N4）。裁判没给出结构化结论时降级为普通气泡。
- **为什么**：低视力用户可以只读/只听结论；「采纳 / 打回 / 打分」出现在要做决定的那一刻（宗旨：互评打分迭代）。
- **借鉴**：LobeHub 调节器「总结讨论并提炼关键结论」；agentchattr「产出阶段在时间线里高亮」。**改动量**：中（前端渲染；若裁判消息已有角色字段，worker 只需补 `kind:verdict`）。**风险**：结论抽取失败要有降级。
- **评审**：Agnes「理由压成一行、别分小节」部分采纳（理由 ≤2 行，分歧按需出现，不强制三段）；Groq「语义 section/h2/button」采纳。

### L4 Hark 负责人的「本轮分工」消息默认折叠成一行
- **现状**：黑底大气泡逐行列出每位成员「擅长…；实测分 +1.8；额度 91%（估算）；在线」，首屏最醒目的是分工明细。
- **改法**：用原生 `<details>/<summary>`：摘要一行 19px「Hark 安排了 4 位：gpt-oss-120b 写代码、llama-4-scout 挑错、granite 审查、qwen3 裁判」，展开看原明细；Hark 的黑色气泡身份色不变。
- **借鉴**：Slack 线程折叠「N 条回复」。**改动量**：小。**风险**：低。
- **评审**：Groq「用 details/summary」采纳；Groq「改成珊瑚色」驳回（珊瑚只给主动作，Hark 的黑色是成员身份）。

### L5 系统通知合并折叠、左对齐、19px
- **现状**：`light-1440-steward.jpg` 资源管家私聊里连续 8 条青色、居中、16px 的「通知：……」（`.note` 第 194 行 16px 居中）。
- **改法**：连续 ≥2 条合成一张「8 条系统通知 · 最近：Muse 成为副负责人 · 10:42 ›」；展开后每条一行时间 + 一句话，左对齐、19px、`<ul>` 列表；样式用漫画「旁白框」（中性浅底 + 现有墨色描边 + 左上「旁白」小贴纸），不用青色、不按发送者分颜色。读屏只播报合并后的那一行（`role="status"`），不逐条播报。
- **为什么**：居中多行文字每行起点不同，最难读；16px 低于 19px 底线。
- **借鉴**：Slack / Discord 合并系统消息。**改动量**：小。**风险**：低。
- **评审**：Groq「保留时间戳、列表结构」采纳；Agnes「左边条像引用，应按发送者着色或用 15px 灰字」驳回（加颜色违背配色收敛，15px 违背底线），改用「旁白」贴纸解决歧义。

### L6 成员详情的 5 个图标标签页加文字
- **现状**：`light-1440-member.jpg` 详情面板 5 个 tab 只有图标（书、脉搏、文件夹、锤子、钥匙）。
- **改法**：每个 tab 图标 + 17px 墨色文字（简介 / 表现 / 项目 / 工具 / 来源与密钥），文字用 `--ink`（对比 ≥7:1）；手机横滑；`role="tablist"` 已有的话补 `aria-label`。
- **借鉴**：Apple HIG 标签栏图标配文字；调研报告原则 3「状态用一句话，不用图标谜语」。**改动量**：小。**风险**：低。
- **评审**：Groq「文字对比要 ≥7:1」采纳为验收标准。

### L7 讨论模式弹层：每个模式一句说明 + 不同图标
- **现状**：`light-390-mode.jpg`：辩论 / 审查 / 自由聊 / 任务都是同一个滑杆图标，无说明。
- **改法**：每项一句可见的 17px 说明（「辩论：两方对立，裁判给结论」「任务：分工做出成品」等），图标各不相同且 `aria-hidden`；整组 `role="radiogroup"`，当前项打勾并写「当前」。→P1-4：主持模式放进同一弹层，说明写「主持人决定谁说话，你随时可暂停」。
- **借鉴**：LobeHub 四种模式各一句适用场景。**改动量**：小。**风险**：低。
- **评审**：Groq「图标 aria-hidden、单选语义」采纳；「说明放 sr-only」驳回（低视力用户要看得见）。

### L8 资源库「API 密钥」：已填 / 未填 / 失败分组
- **现状**：`light-1440-tools.jpg` 26 张密钥卡每张都展开大输入框 + 大按钮，一屏 1.5 张。
- **改法**：顶部一行「已填 N · 未填 M · 验证失败 K」；验证失败置顶并展开；未填折叠为一行「Groq 未填」+ 两个独立的 ≥44px 按钮「去哪复制」「填写」，点「填写」才展开输入框。
- **借鉴**：Vercel 环境变量列表。**改动量**：小。**风险**：低。
- **评审**：Groq「两个操作各自 ≥44px」采纳。

### L9 成员名册：每行两层，顶部只留一个主按钮
- **现状**：`light-1440-members.jpg` 每行 3 行字；第三行「剩 9,037 / 10,000 neurons（本群本地记账；整个主账号共用，其他 Worker 的用量算不进来）（估算）」在每个 Workers AI 成员上重复；顶部「立即探测 / 添加外部 AI成员 / 填 API 密钥」三个同权重按钮。
- **改法**：行第一层「名字 + 可用/不可用文字 + 剩余百分比」，第二层前 3 个擅长标签 +「+2」；额度说明在列表顶部写一次；不擅长只进详情；顶部只留「添加外部 AI成员」为按钮，探测改自动（M5），填 Key 改条件提示（M4）。
- **借鉴**：Discord 成员栏单行；OpenRouter 模型列表一行一模型（调研报告 R2）。**改动量**：小。**风险**：低。

### L10 键盘与读屏：补「跳到主内容」，新控件统一验收
- **现状**：已有 3px 焦点环（`page.html` 第 42、374 行）和 `aria-current`；没有「跳到主内容」链接。
- **改法**：页首加隐藏、聚焦可见的「跳到对话」链接；本清单所有新控件（结论卡按钮、暂停、决策按钮、跳到最新、通知展开）验收时必须：Tab 可达、Enter/空格可触发、焦点环可见、读屏能报出名称与状态。写进 ui_test。
- **借鉴**：WCAG 2.4.1 Bypass Blocks。**改动量**：小。**风险**：低。
- **评审**：两位评审都指出漏了键盘验收 → 采纳；Groq「缺焦点环」驳回（已有）。

## 二、配色 / 可读性

### C1 黄色回到 wizardzines 自己的规则：「一种颜色只管一类东西」
- **现状**：一屏里黄色同时表示：主按钮（风格规定）、侧栏当前项、当前项目、分段控件选中、项目状态「进行中」胶囊（`light-1440-room.jpg`、`light-1440-tools.jpg`）。design-taste 预检：强调色一屏 >4 次就不再指向任何东西。
- **改法**（只在现有配色表内重新分工，不加新色、不动珊瑚和黄色按钮）：黄 = 可点的主按钮（不变）；当前位置 / 选中 = 配色表里已有的 `--orange-light #f9e6d8` 浅橙底 + 现有 2px 墨色描边 + 粗体；状态胶囊 = 中性描边 + 文字，只有「待你确认」用黄（因为它要你点）。浅深两套主题分别测对比。
- **为什么**：低视力用户靠颜色找「下一步」，一色多义会点错。
- **借鉴**：wizardzines 借鉴文档「颜色多但每种只管一类东西」；taste-color「语义颜色令牌」。**改动量**：小（CSS 变量）。**风险**：用户已习惯黄色选中，先在测试清单里让用户对比两版再定。
- **评审**：Groq「保存并验证是黄色、不可改」部分采纳——黄色按钮确属漫画风，故本条改为不动按钮、只把「选中」和「状态」从黄色挪走；Groq「选中改 2px 下划线」驳回（细线低视力难辨，保留色块）。

### C2 「不擅长」标签别用删除线
- **现状**：名册里「中文写作」「长文创作」用删除线表示不擅长（`light-1440-members.jpg`），删除线穿过汉字中部，低视力下像乱码。
- **改法**：分两组：「擅长：」实心标签；「不擅长：」文字前缀 + 2px 实线灰描边空心标签 + 手绘「×」图标（SVG，不用 emoji），灰描边对白底 ≥3:1、文字墨色。
- **借鉴**：调研报告 §6「擅长/不擅长用实心/空心 + 标题区分」（已定原则未落实）。**改动量**：小。**风险**：低。
- **评审**：Groq「虚线框太细」采纳（改 2px 实线）；「✖ 前缀」改为手绘 SVG（design-taste 禁 emoji 图标）。

### C3 「柔和气泡」：系统要求高对比时自动开，其他情况让用户选
- **现状**：成员气泡整块品牌色（蓝、紫），长回答一屏大面积饱和色，深色更刺眼（`dark-390-room.jpg`）。品牌色气泡是用户此前定的规则，默认值不由我们改。
- **改法**：设置 → 外观加「柔和气泡」：气泡用品牌色 12–16% 浅底 + 4px 品牌色左边条（边条对背景 ≥3:1）+ 墨色正文（≥7:1），头像和圆环不变。系统开了「增强对比度」（`prefers-contrast: more`）时自动启用；下一批测试清单里请用户对比两版，由用户决定默认值。
- **为什么**：长文眩光是眼疾用户的实际痛点。
- **借鉴**：Slack / Discord 消息不上底色，靠头像与名字区分。**改动量**：小。**风险**：低。
- **评审**：Agnes「默认就该开，别让视障用户自己改」部分采纳（自动跟随系统高对比 + 交给用户定默认，不越权改用户定过的规则）；Groq「左边条改灰」驳回（会丢身份色）。

### C4 数字等宽、单位统一
- **改法**：额度 / 分数 / 时间所在容器加 `font-variant-numeric: tabular-nums`；单位统一中文（「次」「分钟」），英文单位（neurons）只在详情出现。**借鉴**：调研报告 §7.2。**改动量**：小。**风险**：低。
- **评审**：Groq「每个数字包 span」驳回（容器级设置即可）。

### C5 系统通知等辅助文字提到 19px
- **改法**：`.note` 16px → 19px，行高保持 1.6（与 L5 一起做）。**改动量**：小。
- **评审**：Groq「行高改 1.4、390 宽强制 20px」驳回（行高变小更难读；字号由应用内「文字大小」统一控制）。

## 四、功能新增（不与 P1-2~P1-6 重复）

### N1 「跳到最新」浮钮 + 未读数
- **改法**：用户上翻离底部 >1 屏时，右下出现 ≥56px 圆角按钮，写全文字「新消息 3 条 ↓」；点一下回到底部；不抢焦点。另：现在 `refreshRoom()`（第 823 行）每次都 `scrollTo` 到底，用户在上面阅读时会被拉走——改为只有用户本来就在底部时才自动滚。
- **借鉴**：agentchattr「回到底部箭头显示未读数」；assistant-ui（MIT）吸底逻辑。**改动量**：小。**风险**：低。
- **评审**：Groq「文字写全」采纳；「72px、Alt+N 快捷键」驳回（56px 已超 44px 底线；快捷键对主力手机用户价值低）。

### N2 讨论进行中可「暂停 / 继续」（→P1-4 必备）
- **现状**：忙碌时 `setBusy` 只禁用按钮，没有停止手段。
- **改法**：忙碌时「发送」原位变「暂停」（`aria-label` 同步变，读屏不会再报「发送」）；点后立即显示「已请求暂停，当前这位说完就停」，下一位不启动；中断失败显示「暂停没成功，这位说完会停」；暂停后「继续」接下一位。
- **借鉴**：LobeHub「打断主持人 → 组暂停 → 继续」；agentchattr 循环保护；ChatGPT / Grok 等 App 在发送键原位放「停止」的通用做法。**改动量**：中（worker 需支持「下一位不启动」）。**风险**：状态一致性，要加测试。
- **评审**：Agnes「放页头独立按钮，并给中断失败反馈」——失败反馈采纳，位置驳回（发送键原位是用户最熟悉的位置）；Groq「aria-label 要随状态变」采纳。

### N3 消息内决策按钮（→P1-4、P1-5 复用）
- **改法**：负责人/主持人要用户拍板（付费、命名、代收资源确认）时，消息里给 2–3 个 ≥48px 按钮（「同意」「不同意」「先给我看看」）；点后整组 `disabled`，写「你选了：同意 · 10:42」；服务端幂等（重复点只记一次）。
- **借鉴**：agentchattr Inline decision cards（MIT）。**改动量**：中。**风险**：幂等。
- **评审**：Groq「选后禁用并移出焦点」采纳；「改珊瑚 #D94F3A」驳回（现主按钮墨字配珊瑚已 6.97:1）。

### N4 「听结论」：默认只读结论和分歧，可展开听全部
- **改法**：结论卡上「听结论（约 20 秒）」：只读结论 + 分歧（若有）；旁边小按钮「听每位成员要点」可选。播放中按钮变「停止」，Esc 停止，停止后焦点回到按钮；锁屏可见「Aroomo · 结论」（Media Session，中文标题）。
- **借鉴**：NotebookLM（2026 Webby 获奖，见第六节）把材料变成可听的摘要。**改动量**：中（复用现有 `speechSynthesis`）。**风险**：iOS Safari 后台播放限制，需实测。
- **评审**：Agnes「默认读全部成员是信息过载」采纳（默认只读结论）；两位都要求停止控制 → 采纳。

### N5 完成提示音 + PWA 通知（默认关，用户打开）
- **改法**：设置里「讨论结束时提示音」（默认关，可选音色）；装了 PWA 时可选系统通知「重命名脚本：裁判已给结论」。
- **借鉴**：agentchattr 每成员提示音；调研报告 R16。**改动量**：小（提示音）/ 中（通知）。**风险**：iOS PWA 通知需授权。
- **评审**：Groq「提示音默认关」采纳。

### N6 外部负责人消息显示「已送达 / 已读 / 已回复」
- **改法**：配对接入的外部负责人派活消息下 15px 墨色小字：已送达 → 已读 → 已回复；超时「10 分钟未读」并给「交给副负责人」按钮（衔接已有自动接班）；拿不到读回执时只显示「已送达」。读屏用 `aria-describedby` 关联，不用 assertive 播报。
- **借鉴**：CCCC「stored / delivered / read / reply 分开记录，不假装已读」（Apache-2.0）。**改动量**：中。**风险**：外部智能体不一定回读回执。
- **评审**：Groq「aria-describedby」采纳；「14px、assertive」驳回。

### N7 置顶 = 待办，再点 = 完成
- **改法**：消息操作条「钉为待办」→ 再点「标为完成」（文字按钮）；页头「待办 2」点开列表，完成项收进列表底部「已完成」组，不留在对话视图。
- **借鉴**：agentchattr pinned messages 循环（MIT）。**改动量**：中。**风险**：低。
- **评审**：Groq「完成后收起、用文字按钮」采纳。

### N8 弱网：发送失败保留草稿，可一键重发
- **改法**：输入框内容实时存 `localStorage`（按项目），发送失败时消息留在输入区上方，写「没发出去 · 重发」；刷新页面草稿还在。
- **借鉴**：Agnes 评审补漏；Slack / Discord 「发送失败 · 重试」惯例。**改动量**：小。**风险**：低（不存敏感 Key）。
