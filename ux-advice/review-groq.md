## 1️⃣ 具体条目逐条批评  

### L1 【P0 缺陷】侧栏遮挡  
- **错误**：仅把 `margin-left` 写进同一规则并不能根本解决 **响应式布局** 与 **可视化层级** 冲突，仍然在 1000‑1476 px 区间出现水平滚动，低视力用户会被迫放大页面导致水平滚动失效。  
- **改法**：使用 **CSS Grid** 或 **Flex** 让侧栏脱离文档流，`main` 使用 `grid-template-columns: var(--side) 1fr;` 并在媒体查询里 `grid-template-columns: 0 1fr;`（侧栏隐藏时）。同时在 `html` 上强制 `overflow-x:hidden` 防止意外滚动。  
- **把握度** 92%  

### L2 项目页头首屏过满  
- **错误**：把标题压到 1‑2 行、把成员列表折叠为胶囊会 **破坏已定的漫画杂志风**（粗描边硬投影），且 **“胶囊”** 采用黄色背景违背 **C1** 颜色语义。  
- **改法**：保持原有 **“阵容·4 位”** 横滑卡的视觉风格，只在 **“折叠”** 时使用 **ARIA `aria-expanded`**，并在折叠状态下提供 **键盘快捷键**（Enter/Space）展开。页头高度限制在 **160 px** 必须通过 **`max-height` + `overflow:hidden`** 实现，且 **不改变颜色**。  
- **把握度** 87%  

### L3 结论卡与最新结论行  
- **错误**：在页头加入 **“最新结论：……（朗读）”** 链接会导致 **页面结构层级混乱**，朗读按钮若不使用 **`role="button"`** 与 **`aria-live="polite"`**，屏幕阅读器会忽略。  
- **改法**：把结论卡放在 **`<section aria-labelledby="conclusion-heading">`**，标题使用 **`<h2 id="conclusion-heading">`**，朗读按钮必须是 **`<button>`** 并绑定 **`SpeechSynthesisUtterance`**，并在 **`prefers-reduced-motion`** 时禁用动画。  
- **把握度** 81%  

### L4 Hark 本轮分工折叠  
- **错误**：折叠为单行文字后 **信息密度** 仍然极高，低视力用户在 **放大 150 %** 时仍会被截断，且缺少 **可访问的展开控件**。  
- **改法**：使用 **`<details>` / `<summary>`** 原生可折叠组件，确保 **键盘可操作**，并在 `summary` 中加入 **`aria-controls`** 与 **`aria-expanded`**。文字应保持 **19 px**（不可低于正文），颜色使用 **珊瑚**（已定主色）而非黑底。  
- **把握度** 78%  

### L5 系统通知合并折叠  
- **错误**：把多条通知合并为 **“8 条系统通知·最近：...”** 的单行卡片，**失去时间顺序**，对低视力用户的 **时间感知** 产生障碍；且使用 **青色大底** 与 **黄色语义冲突**。  
- **改法**：合并后仍保留 **时间戳**（如 “3 分钟前”）在每条子项前，用 **`<ul>`** 列表结构，背景改为 **中性浅灰**，左侧 4 px **灰色描边**（不使用黄色），并在 `aria-live="polite"` 区域实时更新。  
- **把握度** 85%  

### L6 成员详情图标标签缺文字  
- **错误**：仅加文字 **“15–17 px”** 仍然违背 **对比度** 要求，若文字颜色使用 **默认灰** 与背景灰对比不足（< 4.5:1），低视力用户无法辨认。  
- **改法**：文字颜色必须 **≥ #000000 @ 70 %** 与背景对比 ≥ 7:1（WCAG AA），并使用 **`font-weight:600`** 提升可读性；在移动端提供 **水平滚动** 同时 **`aria-label`** 说明每个标签的功能。  
- **把握度** 90%  

### L7 讨论模式弹层图标统一  
- **错误**：仅在图标旁加 **17 px 说明文字** 并不解决 **键盘导航** 与 **屏幕阅读器** 的可达性；图标仍然是 **装饰性 SVG**，若未加 `role="img"` 与 `aria-label`，会被朗读为 “图像”。  
- **改法**：把每项包装成 **`<button class="mode-option" aria-pressed="false">`**，内部图标使用 **`<svg aria-hidden="true">`**，文字使用 **`<span class="sr-only">`** 为盲人提供完整描述；并在 **`prefers-reduced-motion`** 时关闭弹层动画。  
- **把握度** 84%  

### L8 资源库 API 密钥页折叠  
- **错误**：折叠未填项为 **单行文字**，但 **“Groq 未填 · 去哪复制 › [填写]”** 中的 “去哪复制” 文字不具备 **可点击区域**，导致 **点击目标过小**（低视力用户难以命中）。  
- **改法**：把 **“去哪复制 ›”** 与 **“[填写]”** 分别做成 **宽度 ≥ 44 px** 的按钮，使用 **`button`** 元素并提供 **`aria-describedby`** 解释操作；未填状态使用 **浅黄色背景**（但必须与 **C1** 颜色语义冲突，改为 **中性灰**）。  
- **把握度** 80%  

### L9 成员名册行信息过载  
- **错误**：把 **“剩 9,037 / 10,000 neurons（本群本地记账…）”** 直接放在每行，**文字密度** 极高，放大后会导致 **水平滚动**；且 **“neurons”** 英文单位在中文环境下破坏阅读流畅度。  
- **改法**：在表格中使用 **`<abbr title="神经元">neurons</abbr>`**，并把 **额度** 只保留 **“剩 90%”** 与 **圆环**，其余解释放在 **`<details>`** 中，默认折叠。所有文字必须 **≥ 19 px**，颜色对比 ≥ 7:1。  
- **把握度** 88%  

### C1 颜色语义混乱  
- **错误**：提议把 **黄色** 只用于 “当前位置”，但 **“保存并验证”** 按钮已固定为黄色，**不可改**（按钮是主动作，必须保持珊瑚），若改色会违背 **不可改** 约束。  
- **改法**：**不**改动已有黄色按钮，改为在 **CSS** 中为 **“当前位置”** 添加 **`border-bottom:2px solid var(--yellow)`** 而非背景色；保持按钮原色不动。  
- **把握度** 95%  

### C2 “不擅长”标签使用删除线  
- **错误**：删除线穿过汉字导致 **乱码感**，但提议的 **空心虚线框** 仍然使用 **细线**，在 **低视力**（< 12 pt）下难以辨认。  
- **改法**：改为 **实心灰色圆点** + **文字前缀 “✖ 不擅长”**，颜色使用 **#666**，对比度 ≥ 4.5:1；并在 **`aria-label`** 中说明 “不擅长”。  
- **把握度** 92%  

### C3 柔和气泡开关  
- **错误**：默认关闭，**但**打开后使用 **12–16% 浅底** 与 **4 px 左边条**，左边条颜色仍为品牌色（蓝/紫），在 **暗色模式** 下对比度可能低于 **4.5:1**，导致低视力用户看不清文字。  
- **改法**：左边条改为 **#555**（暗模式）或 **#ccc**（亮模式），并在 **CSS** 中使用 **`@media (prefers-color-scheme: dark)`** 调整；同时在 **设置** 中提供 **“高对比度气泡”** 选项。  
- **把握度** 78%  

### C4 数字等宽、单位统一  
- **错误**：仅在 CSS 中加入 `font-variant-numeric: tabular-nums` 并不能解决 **中文单位** 与 **英文单位** 混排导致的 **阅读节奏** 问题；更重要的是 **数字** 在 **放大 200%** 时仍会出现 **字形失真**。  
- **改法**：使用 **Open‑Type** 字体的 **`tnum`** 功能，并在 **HTML** 中把所有数字包装在 **`<span class="num">`**，确保 **`line-height`** 与 **`letter-spacing`** 适配放大。  
- **把握度** 84%  

### C5 系统通知、状态文字最小 19 px  
- **错误**：仅把 `.note` 改为 19 px 并未检查 **行高** 与 **字间距**，在 **放大** 时仍可能出现 **文字截断**。  
- **改法**：设定 **`line-height: 1.4`**，并在 **媒体查询** 中对 **`@media (max-width: 390px)`** 强制 **`font-size: 20px`**，确保 **触控目标** ≥ 44 px。  
- **把握度** 86%  

### M1 侧栏导航重复  
- **错误**：直接删除 “对话” 项会导致 **键盘焦点顺序** 变化，且 **ARIA `aria-current`** 失效，屏幕阅读器无法指示当前对话。  
- **改法**：保留 “对话” 项但改为 **`role="navigation"`** 的 **`aria-label="当前对话"`**，并在点击后使用 **`router.replace`** 不产生页面刷新；在 “项目” 页面加入 **`aria-controls`** 关联。  
- **把握度** 89%  

### M2 “成员与角色 / 打分 / 成员互评” 入口合并  
- **错误**：把这三项全部搬到 **结论卡** 中会导致 **功能层级不一致**，且 **结论卡** 本身已经占据 **视觉焦点**，低视力用户在 **朗读** 时会错过这三个操作。  
- **改法**：在 **结论卡** 下面添加 **固定底部工具栏**（`position: sticky; bottom:0`），每个按钮宽度 ≥ 44 px，使用 **`aria-label`** 明确功能；保留 **`+` 菜单** 仅作快捷入口，不删除原入口。  
- **把握度** 83%  

### M3 “模式” 选择器出现两次  
- **错误**：建议只保留输入栏芯片，但 **输入栏** 本身在 **低视力** 时文字放大后会导致 **芯片宽度不足**，用户无法点击。  
- **改法**：把 **模式文字** 放在 **`<button>`** 中，宽度自动适配文字，最小宽度 44 px，使用 **`aria-pressed`** 表示当前模式；在 **`prefers-reduced-motion`** 时关闭弹层动画。  
- **把握度** 80%  

### M4 “填 API 密钥” 入口统一  
- **错误**：把成员页按钮改为文字链 **“缺 3 个来源的 Key → 去资源库填”**，但 **文字链** 颜色默认使用 **灰色**，对比度可能低于 4.5:1，且 **链接** 失去 **按钮语义**（ARIA `role="button"`），导致键盘用户无法激活。  
- **改法**：使用 **`<a class="button-like">`**，并在 CSS 中强制 **`color: var(--coral)`**、**`background: transparent`**、**`border: 2px solid var(--coral)`**，确保对比度 ≥ 7:1。  
- **把握度** 88%

- **错误**：自动后台探测会产生 **网络请求**，在 **低视力用户** 使用 **屏幕阅读器** 时可能导致 **页面卡顿**，且 **未提供** 进度反馈，违反 **WCAG 2.4.7**（可见焦点）。
