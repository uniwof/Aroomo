## 0. 一句话
一个**24 小时在线的网页版“AI 公司”**：把用户能免费用到的所有模型/智能体抽象成“AI成员”（一个模型一张卡，带品牌头像、额度环、在线点），用户每发一个需求就是一个“项目”，负责人（目前是 Hark）按每个成员的擅长岗位、剩余额度、在线状态挑人分角色，让它们在群里分工、互相挑错、裁判收尾；额度用完自动换人。全部以**免费**为目标。

## 1. 用户的工作规矩（必须遵守，否则用户会不满意）
1. **分批开发、逐批验收**：每批做完交给用户试用；用户说“通过”才开始下一批（用户拒绝了“自动继续”的折中）。
2. **每批必须附“用户测试清单”**：每个功能写 ①发哪句话 / 点哪里 ②看到什么算通过 ③不对时回报什么。句子可直接复制或语音念出，步骤少看屏、大字。
3. **完全免费优先**：能免费就免费；只有免费确实达不到效果时才推荐付费，并说明为什么免费不够、多少钱、换来什么；付费永远要用户确认。
4. **不闭门造车**：动手设计前先调研同类产品/创作者；设计、提示词、方案定稿前让**其他厂商的模型做反对式评审**（要求它们别附和、敢反驳；我方不同意也要反驳；取双方最好的）。
5. **用户发过的资料都要用上**：开工前先查已吸收的技能和资料（UI 组件、设计品味、工作流等），能借鉴就借鉴。
6. **所有需求点都要实现**：用户原话“不管你是借鉴也好，还是全部重新做也好，最终一定要把我这些需求都满足”。
7. 回复不要自我辩解、不要防御性措辞；不确定也给出标注过的判断。
8. 隐私第一；密钥绝不出现在消息、文档、仓库里（只写环境变量名）。
9. 命名、Logo、域名购买都要用户拍板，不得擅自决定。

## 2. 完整需求清单（按用户原话整理，2026-10-23 06:59–08:10）

### 2.1 成员（统称“AI成员”）
- 统一称呼 **“AI成员”**（用户定名），不区分模型 / 智能体 / 网页型；界面不按类型分组，类型只作为详情里的“连接方式”。
- **名字用英文原名**（如 gpt-oss-120b、Gemini 2.5 Flash），不起中文名，方便用户认出是哪个模型。
- **一个模型一张卡**；同一模型的多个渠道（官方 API、各中转站/公益站、网页端、本地显卡）是它的**“来源”**，列在简介里（每个来源的额度、可用状态）。
- 要把用户**所有中转站能用的模型、所有已对接的 API、网页型免费工具**（例如用户提过的 Agnes AI 的免费生图模型，要写明免费到哪天）尽量全部列出来，额度一定标清楚。
- 外部智能体也是成员，要能接入：**Poke（API）**、**同一内网 / Tailscale** 的智能体（CCCC、OpenCode、Claude Code 等）、Webhook、Telegram Bot、网页型（背后由浏览器代发指令）。
- 简介里写明**执行能力标签与配置**：自带电脑/沙盒、浏览器、远程浏览器、可切代理 IP（国家/住宅）、能收验证码、能注册、能查信息。以后用户下“注册/查信息”类命令时，负责人按这些标签派单。
- **工具不是成员**：显卡、电话号码、沙盒、代理节点、临时邮箱、浏览器等只能被调用、不会主动干活的，放进“资源库 → 工具与算力”（2026-10-23 起「工具库」改名「资源库」）一栏。成员卡写“可调用的工具”；工具卡写“谁能用、权限、额度/费用”。显卡是算力来源，上面跑的模型才是成员。

### 2.2 招人宗旨与标签
- 成员以**模型**为单位入选，不以平台入选；不论从哪扫描到（网页、API、中转站、本地显卡）。
- 宗旨：**为每个模型找到适合它的岗位**，哪怕作用很小也招；只有任何岗位都做不好、公认没用的才不招。
- 用户强调：“便宜小模型做判断/巡检”**只是举例，不是规则**。标签一律**以实际效果为准**。
- 标签生命周期：入职时按网友/社区评价给初步标签（附来源链接+日期，例如“Gemini 适合写小说”）→ 每次项目结束，**成员互评 + 用户打分 + 实测**，持续更新“擅长 / 不擅长”。
- 每个成员必须有清晰的**擅长岗位标签 + 不擅长事项**，派工按标签走。

### 2.3 头像、额度环、状态点、消息样式
- 头像 = 品牌 Logo（或抽象吉祥物）；头像外一圈**额度环**（像电量）：能实查就实查，查不到就按该 API/中转站公开的免费额度推算，并标“估算”。
- 头像旁**绿点 / 红点**表示可用 / 不可用（休息、限流、额度用完、缺密钥、离线）。
- **消息气泡底色 = 该品牌 Logo 主色**，与头像颜色一致（例：Grok 黑；Hark 是负责人，也用黑）。文字黑/白按对比度自动选。
- 消息布局：头像在左；右侧上面是**用户名**、下面是消息，二者与头像水平/垂直对齐。用户名 = 产品/模型名 +（括号里负责人给它安排的角色），如 `gpt-oss-120b（程序员）`。
- 点头像 → **详情页**：介绍、剩余额度（数字/单位/来源）、怎么获取更多额度、属于哪个中转站/哪些来源可调用、什么时候恢复可用、数据限制（上下文、速率）、隐私、擅长标签（带出处）、执行能力、可调用工具、**参与历史**。

### 2.4 项目与对话
- 每个需求/对话 = 一个**项目**（包括派给某个智能体的单独注册任务）。
- 新建对话时，用户可**自己勾选哪些成员加入**；或让负责人按能力自动推荐（例：写小说类议题就挑擅长文字的）。
- 成员的**参与历史**：几年几月几日几点几分参与了哪个项目、扮演什么角色、完成/进行中，可点进房间。
- 页面**顶部搜索框**：搜索所有对话，结果显示每条来自哪个房间/项目。
- 账号界面默认能看到所有可加入的 AI成员。

### 2.5 界面风格
- **日式极简**；**主色调珊瑚色**（用户喜欢）：正文深色保证对比度，珊瑚色用于主按钮/选中/重点，珊瑚文字用加深档并过 WCAG 4.5:1。
- 手机优先（用户用 iPhone）、大字（正文 ≥19px）、点击区域 ≥44px、深色模式自动+手动切换、颜色不能是唯一信息载体（红绿点旁要有文字）。
- 界面参考由开发者自己找（用户放权：“不一定参考智能体产品，你自己分析和哪些项目类似”）；拆解参考时**只拆国外产品**，不拆国内。

### 2.6 资源库（装备库）
- 成员之外一切可借用的东西统一放一个库，四类：①**工具**（可调用：API、显卡、号码、沙盒、TTS，如 Fish Audio）②**素材**（音效、配音音色、视频样片、图片/风格参考）③**参考**（提示词库、UI 组件站、网页设计参考）④**方法**（技能/工作流/做法指南，如“哪类视频用 Remotion、哪类用生视频”）。
- 每条：类型、能做什么（标签）、怎么用（调用方式或网址）、免费额度/到期日、最后验证时间、状态、出处。到期前提醒，定期巡检失效即标记。
- 规则：**成员开工前先查资源库**，有现成的直接用，没有再上网搜，搜到的好东西回填。
- 原因（用户）：现在资源在某个模型里整理会耗该模型额度，别的模型看不到，复用还得手写交接提示词。所以要一个所有成员都能直接读取的统一装备库（对外开 API/MCP）。
- **资源管家**：一名专职 AI成员（它会干活，所以是成员不是工具），只有它写入，其他成员只读。职责：用户在**置顶私聊**里丢帖子/链接即入库；定时自主去 X、论坛抓免费额度/羊毛/试用；按官方页面核实后分类、记录到期日、提醒。方案见 `resource-steward-plan.md`（每月 0 元：Cloudflare Cron 抓取+脚本初筛去重+模型只做批量分类提取）。**模型实测和 Groq/Agnes 外部评审尚未完成。**
