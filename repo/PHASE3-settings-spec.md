## 设置页分类（按用户当前已接入资源归类）
1. 模型 API（品牌官方）：Workers AI、Groq、Gemini、NVIDIA、Agnes AI、Vyce AI、OpenCode、Elorian

3. 智能体：API 型（Poke、Simular Sai）、MCP/ACP 型、局域网/Tailscale 型（CCCC、OpenCode、Claude Code，经 Tailscale Funnel 或 cloudflared 小桥）、Webhook/Telegram Bot 型、远程（Muse、Hark）
4. 沙盒：E2B、Daytona、InstaBox、Freestyle 云浏览器、Modal
5. 显卡 / 算力：Modal、Kaggle、Lambda、Lightning AI、Beam
6. 云手机 / 电话：Airtap（待确认类型）、Phonebox（号码/短信）、Telegram API
7. 网页型：站点 URL、可用模型、试用截止日期（到期提醒）、账号密码（加密保存）、登录方式；支持“让任意成员模型代为注册/登录/填写”或用户手填；默认头像 = 平台 Logo
- Saperly：类型待确认

## 技术要点
- 密钥 AES-GCM 加密存 DO，主密钥用 Worker Secret；前端只显示掩码
- 每项“测试连接”按钮 + 轻量缓存探测
- 适配器：OpenAI 兼容（覆盖多数中转站）/ Gemini / Anthropic / MCP / Webhook / 浏览器
- 网页型代注册需浏览器运行环境（Cloudflare Browser Rendering 或沙盒）；验证码/手机验证会卡住时转交用户；遵守用户注册约定（真实信息、不批量）
- 新增资源只改配置，自动出现在成员库

## 宗旨：为每个模型找到适合它的位置（用户 2026-10-23）
- 招人标准不是“综合最强”，而是“在本公司至少有一个它能发挥作用的岗位”，哪怕作用很小也招。
- （用户强调：“小模型做判断/巡检”只是举例，不是规则。）岗位标签一律以实际效果为准：每完成一次项目，成员互评 + 用户打分 + 实测记录，按效果给出/修正擅长岗位；便宜、小巧本身不等于适合某岗位。
- 每个 AI成员必须有清晰的“擅长岗位”标签 + 不擅长事项，派工按标签走；标签来自效果数据（项目后互评、用户打分、实测），不按价格或体量预设。
- 只有在任何岗位上都发挥不了作用的才不招。
- 成员以模型为单位，网页/API/中转站/本地显卡只是来源。

## 成员 vs 工具（用户 2026-10-23）
- 一个模型只建一张成员卡；简介里列出“来源”：哪些中转站/网页/API/本地支持它，各自额度与可用状态。
- 不会自己干活、只能被调用的东西（显卡、电话号码、沙盒、代理节点、邮箱、浏览器等）不做成员，归入“工具库”，单独一栏。
- 显卡算“算力来源”：在显卡上跑的模型才是成员，显卡记在它的来源里。
- 成员卡写明“可调用的工具”；工具卡写明“谁能用、权限、额度/费用”。派工时按任务所需工具筛选能用该工具的成员。
- 标签生命周期（用户 2026-10-23）：入职时按网友/社区评价给初步标签（如“擅长写小说”），不按大小或价格预设；之后每次共同完成项目，成员互评 + 用户打分，持续更新迭代标签。

## 资源库（用户 2026-10-23）——成员之外的一切可借用的东西
- 三类同库：①工具（可调用：API/显卡/号码/沙盒/TTS，如 Fish Audio s2.1-pro-free，免费至 2026-11-30）②收藏馆（网页资源：提示词库、UI 组件站、网页设计参考、视频样片、配音音色、生图风格参考等）③技能（现成工作流/skill）。
- 每条记录：类型、能做什么（标签）、怎么用（调用方式或网址）、免费额度/到期日、最后验证时间、当前状态、谁推荐/出处。到期前提醒，定期巡检失效即标记。
- 规则：AI成员做任务前先扫资源库，有现成的直接用，没有再上网搜；搜到的好东西回填资源库。
- 初始数据：从 Hark 已吸收的资料（knowledge/absorbed-resources、video-making-resources、design-taste、已装技能）导入。
- 平台路线：先做网页端；网页体验满意或确实受限时再做 Windows 客户端（用户 2026-10-23 改）。
- 资源库细分（用户 2026-10-23 补充）：①工具（可调用）②素材（音效、配音音色、视频样片、图片/风格参考）③参考（提示词、UI 组件、网页设计）④方法（技能 + 做法指南，如“哪类视频用 Remotion / React 代码动画 / 生视频做”）。统一一个资源库、按类型筛选，不另建系统；统一用“能做什么”标签检索。
- 【点子，用户 2026-10-23，待定】资源库专职维护者“资源管家”：本身是能干活的 AI，所以算成员而非工具。职责：用户把帖子/链接丢给它即入库；定时自主去 X/推特、论坛等抓取符合公司需求的免费额度、羊毛、免费试用平台；按官方页面核实后分类入库（工具/素材/参考/方法），记录到期日、失效标记、到期提醒。用户只需和它对话。运行形式待定：候选为 Hark 定时任务、Cloudflare Workers Cron 常驻巡检，或两者结合（CF 定时抓取+模型整理）。暂只记录，群聊/资源库落地后再做。
- 【原因，用户 2026-10-23】“装备库”统一：现在资源在某个模型那里整理，会耗该模型额度，其他模型也不知道，复用还得让它写提示词转交。目标：一个统一的装备库（工具+收藏站点及用途+技能），所有成员都能直接读取；只有资源管家负责写入/维护，其他成员只读、按需取用。实现方向：装备库对外提供一个统一读取接口（如 MCP 服务或简单 API），每个成员开工前先查，免去手写交接提示词。
- 【用户 2026-10-23】用户与资源管家有一个固定私聊（置顶），在里面丢链接、问装备库、听它汇报新发现的羊毛/到期提醒。
- 【用户已同意 2026-10-23，排入第 2–4 批】①装备库对外开 MCP 接口，Claude Code/Cursor/Hark 等外部工具也能直接读；②新成员“试用期”：入职时自动跑一套固定小考题，初始标签先有实测分；③来源心跳：每天自动测一次所有模型来源是否还能对话，派工不派到已失效来源；④项目做完自动沉淀成“方法”（工作流/SOP）入装备库；⑤整个公司配置一键导出备份（隐私、迁移）。建议按 MVP 顺序分批做，不一次全做。
