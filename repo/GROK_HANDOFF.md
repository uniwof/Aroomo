## 0. 一句话
Aroomo 是用户的网页版「AI 公司」群聊：把用户能免费用的所有模型/智能体做成「AI 成员」，按擅长岗位 × 剩余额度 × 在线状态派活。线上地址 https://chat.pcmanai.com/ （Cloudflare Worker `ai-groupchat` + SQLite 版 Durable Object）。

## 2. 工作原则（必须遵守）

检索顺序（两者都要做）：

## 4. 未完成需求（按顺序做）
### P1-1 模型能力分类与负责人资格（试点，先做）
- 成员可多选能力标签 `chat/vision/reason/code/write/image/video/audio`。
- 生图、生视频、语音、写作专用和网页成员可当执行成员，**不能当负责人**。
- 负责人候选须：能文字对话、上下文足够（建议 ≥32k）、支持工具调用。**后端与前端都要校验**，防止专用模型绕过下拉限制。
- 平台 / 模型同步：新增中转站或平台后读取 `/v1/models`；已有模型新增来源，新模型建卡且能力先标「待核实」；负责人选择器从服务端实时拉取。

### P1-2 网页成员（代发）
- 网页 / 客户端型模型作为正常 AI 成员出现在成员列表、MCP 和负责人视图中，但不必知道 Aroomo 存在。
- 任务进入 `kind=web` 队列，由有浏览器的代发员（Hark 远程浏览器或用户授权的桌面桥接智能体）领取，向目标网页发送带前情、角色、输出格式的完整提示，把回复回传群聊并标「经代发」。
- 同一项目复用同一网页会话；默认 10 分钟超时自动改派；签到也由代发员执行。仅客户端型品牌必须用用户电脑桥接，操作前需用户同意。

### P1-3 点子库
- 点子与项目分开。点子是存档：当时的想法、计划形式、预期效果、沟通摘要、来源、标签、状态（正在做 / 暂时收藏 / 已放弃）；不能因未落地就当成项目。
- 新建项目可关联点子；关联后点子内容作为项目背景注入所有成员上下文，项目结论可回写点子。
- 预填：老照片修复定制服务、提示词策展站、古风助眠 YouTube、激光切割拼装图纸、新词站 / AI 出海、pcmanai.com 电脑维修 / 数据恢复 / AI 服务。

### P1-4 群聊主持模式 + 快速建项目
- 项目可切换「我来主持」/「负责人主持」。
  - 我来主持：用户可 @单个成员、@所有人；回复消耗被调用成员自己的额度；不 @ 时显示按主题、能力标签、在线状态、剩余额度排序的推荐成员。
  - 负责人主持：主负责人分析需求、分工派活，副负责人按既有接班规则接管；用户 @ 某成员时优先满足点名。
  - 用户自己发消息不消耗任何 AI 成员额度，只有实际调用成员回复才消耗。
- 快速建项目：不强制预选成员；「快速项目」默认所有成员进入候选，写需求后由负责人派工，或用户在「我来主持」下自行 @。普通项目仍可手动选成员。

### P1-5 主负责人代收资源（用户 2026-10-24 新增，排在主持模式之后）
用户以后可能在外部智能体 App（主负责人所在平台）里直接把资源发给主负责人。
- 新增操作员接口 + MCP 工具 `submit_resource`（字段：`url` / `text` / `note` 备注 / `source` 来源）。主负责人用**操作员令牌**把资源静默送进资源库。
- 走与资源管家**同一条流水线**：去重 → 分类 → 官方页逐字核实后才标「已核实」。
- 不在群聊 / 私聊刷屏；只在资源库条目上标「来源：主负责人代收」，并计入每周汇总的「新增」。
- 副负责人接班后同样可用。
- 资源管家仍是**唯一**的分类与核实执行者；主负责人只负责投递。
- **常驻规则**（解决"只发链接时主负责人怎么知道要存"）：
  1. 在 `skills/ai-groupchat-operator.md` 和配对开场白里写死：「用户在你所在平台直接发来的链接 / 文件 / 资源，若没有别的指令，默认调用 `submit_resource` 投递资源库，只回一句"已收进 Aroomo 资源库"，不追问；用户明确说别的用途时按用户的来。」
  2. `GET /api/lead/brief`（MCP `get_brief`）返回里带 `standingRules`，含同一条规则——主负责人上下文被清空或副负责人接班后重读即可恢复。
  3. 配对成功时页面提示用户：「以后直接把链接发给负责人即可」。
- 验收：令牌鉴权（无令牌 / 错令牌 / 已吊销令牌被拒）；重复提交去重；未核实条目不显示为已核实；`test_live.py` 新增用例，并检查技能文件与 `get_brief` 都含该常驻规则。

### P1-6 Cloudflare 额度保险
- 目标：防止 Aroomo 把用户 Cloudflare 免费额度（Workers 请求、Durable Object、Workers AI 等）用穿导致整站不可用。
- 细则（用户 2026-10-24 已确认，纳入实现和测试）：
  1. **用量显示**：顶部显示当天 Worker 请求用量。Workers Free 为 100,000 次/日，UTC 00:00 重置；达到 80% 时提醒用户；超限时 Cloudflare 返回 Error 1027，前端要识别并显示明白的提示。
     - 验收：模拟用量 79% / 80% / 100% 与 1027 响应，UI 显示正确；`test_live.py` / `ui_test.py` 加用例。
  2. **发件箱**：用户消息先写入浏览器 IndexedDB（不可用时 localStorage）发件箱，再发送；网络失败或 1027 时标记「待发送」，恢复后自动补发；每条用客户端消息 ID（`cid`）去重，服务端按 `cid` 幂等，确保不丢不重。
     - 验收：断网 / 1027 下发 3 条，恢复后各出现恰好一次。
  3. **备用入口**：用第二个免费 Cloudflare 账号部署备用 Worker 入口；主入口不可用（1027 / 5xx / 超时）时前端自动切换到备用入口。必须保证数据一致——不得形成互不相通的两套数据（备用入口应读写同一份数据，或经主账号数据层代理 / 同步）。**你需先提出方案给 Hark 审核，通过后再实现。** 凭据由用户另行提供限权令牌，不得把任何密钥写入仓库或交接包。
     - 验收：主入口模拟 1027 时消息经备用入口写入，切回主入口后能看到同一条消息。
- **费用红线**：不升级 Workers Paid、不付款。
